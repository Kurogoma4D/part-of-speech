# 書き換えガイド

歌詞や台詞を 文脈に沿った意味カテゴリのラベルに置き換えるときの出力形式・ラベルの選び方・粒度を定める。LLM（Cloudflare Workers AI）に分かち書きとラベル付けをさせるプロンプトと、その出力を機械的に検証する処理の根拠となる。

## 1. 出力形式

LLM は最終文字列を直接書かず、原文を欠落なく分割した JSON を返す。最終文字列は BFF が JSON から組み立てる。

### 1.1 JSON スキーマ

```json
{
  "type": "object",
  "required": ["tokens"],
  "additionalProperties": false,
  "properties": {
    "tokens": {
      "type": "array",
      "minItems": 1,
      "items": {
        "type": "object",
        "required": ["src", "label"],
        "additionalProperties": false,
        "properties": {
          "src": { "type": "string", "minLength": 1 },
          "label": {
            "type": ["string", "null"],
            "pattern": "^[\\p{Script=Han}\\p{Script=Hiragana}\\p{Script=Katakana}A-Za-z0-9ー]{1,10}$"
          }
        }
      }
    }
  }
}
```

- `src`: 原文の断片。
- `label`: `src` に当てるラベル。原文のまま残す断片は `null`。

`label` の `pattern` は BFF の検証（2 章）が適用する。JavaScript の `RegExp` に `u` フラグを付けて評価する。Workers AI の `response_format` には `pattern` を除いた構造だけのスキーマを渡し、`pattern` の解釈には依存しない。

### 1.2 最終文字列の組み立て

`tokens` を先頭から順に、`label` が文字列なら `[` + `label` + `]`、`null` なら `src` をそのまま連結する。括弧は半角の `[ ]` に統一し、全角の `［ ］` や `【 】` は使わない。ラベルの間に空白を補わない。空白は原文にあるものだけを残す。

### 1.3 保持するもの

次のものは `label` を `null` にして原文のまま残す。

- 空白と改行（連続も含めて原文どおり）
- 記号（`！？、。…〜` などの句読点・記号類）
- 絵文字
- `笑` と `w`（`W`、`ｗ`、`Ｗ` を含む）
- 伸ばし棒 `ー`、小書き文字（`ぁぃぅぇぉっゃゅょ` と対応するカタカナ）。語尾の `ゥ` `ォ` は直前のラベルの外に残す
- ひらがなだけの機能語（助詞・助動詞・補助動詞などの付属語。`は` `も` `が` `ね` `です` `て` など）

上記以外の断片は、必ずラベルを当てる。ひらがなだけの内容語（`おはよう` など）にはラベルを当てる。

## 2. 検証ルール

BFF は LLM の応答を次の順で検証し、1 つでも満たさなければ不正な応答として扱う。

1. JSON が 1.1 のスキーマに合致する。`label` の `pattern` もここで検証する。
2. すべての `src` を連結した文字列が入力と完全に一致する（空白・改行を含む）。
3. `label` が文字列の場合、`label` と `src` が同一でなく、`src` が空白のみでない。
4. `label` が文字列の場合、文法ラベル（3.2）でない。
5. `label` が `null` の場合、`src` は 1.3 の保持対象（記号など、およびひらがなだけの断片）だけで構成される。
6. `label` に括弧 `[ ] ［ ］ 【 】` と改行を含まない（1.1 のパターンで検証する）。

次の項目は検証せず、プロンプトで指示する。

- 同じ語には同じラベルを当てる（リフレインは同じラベル列になる）。
- 1 ラベルが何を指すかは 4 章の粒度ルールに従う。

## 3. ラベルの選び方

ラベルは意味カテゴリと発話機能だけを使う。文法ラベルは使わない。

1. 定型句・掛け合い・感嘆など、句や文の役割が明らかなものは発話機能ラベルにする。
2. 内容語（名詞・動詞・形容詞・副詞など）と固有名詞は、文脈に沿った意味カテゴリラベルにする（`いい` は `[評価]`、`天気` は `[気象]`）。
3. 機能語（助詞・助動詞・補助動詞などのひらがなだけの付属語）はラベルを当てず、原文のまま残す。

### 3.1 推奨ラベル

| 系統 | ラベル |
| --- | --- |
| 意味カテゴリ | 人名、地名、国名、企業名、ユニット名、あだ名、敬称、天体、気象、場所、色、味、季節、体の一部、時間、期間、数字、果物、衣類、幻獣、兵器、必殺技、移動、停止、視覚、愛情、期待、約束、再会 |
| 人称 | 一人称、二人称、三人称 |
| 発話機能 | 挨拶、感謝、呼びかけ、返事、問いかけ、合いの手、掛け声、感嘆、奇声、命令、要求、願望、肯定、否定、宣言、評価、暴言 |
| 外国語 | 英語、アルファベット |

### 3.2 使わないラベル

次の文法ラベルは使わない。BFF は該当するラベルを不正として扱い、再推論の対象にする。

- 品詞名: 名詞、動詞、形容詞、形容動詞、副詞、連体詞、接続詞、感動詞、助詞、助動詞、代名詞
- 細分類: 格助詞、係助詞、副助詞、接続助詞、終助詞、補助動詞、固有名詞、形容詞語幹、可能動詞 など、上記の品詞名で終わるもの
- 活用形: 連用形、未然形、仮定形、命令形、連体形、終止形、意志形 など `形` で終わる活用の名称
- 語幹

### 3.3 自由にラベルを作る場合

推奨ラベルに適切なものがないときだけ作る。

- 短い名詞句にする（10 文字以内、漢字・ひらがな・カタカナ・英数字・`ー` のみ）。
- 原文の語そのものをラベルにしない。
- 括弧と空白を含めない。
- 同じ意味には同じラベルを使い、似た語で表記を揺らさない。

## 4. 粒度ルール

- 既定は 1 形態素 1 ラベルにする。ただし機能語は分けて残す。
- 次の場合は複数の形態素を 1 つのラベルにまとめる。
  - 姓名や複合名称のように、全体で 1 つの固有名詞になる（`山田太郎` は `[人名]`）。
  - 定型句として 1 つの発話機能を持つ（`こんにちは` は `[挨拶]`）。
  - 活用語尾を含めて 1 つの動作を表す（`愛してる` は `[愛情]`）。
- 掛け合いは括弧付きの記号を保持したまま、括弧内も別々に分割してラベルを当てる。
- 句をまとめた結果、ラベルが原文の語そのものになる場合は、まとめずに分ける。

## 5. 入出力例

各例の `tokens` を 1.2 の規則で連結した結果が `output` である。`src` を連結した結果は `input` に一致する。

### 例 1 挨拶と人名

```json example
{
  "input": "こんにちは、田中さん！",
  "tokens": [
    { "src": "こんにちは", "label": "挨拶" },
    { "src": "、", "label": null },
    { "src": "田中", "label": "人名" },
    { "src": "さん", "label": "敬称" },
    { "src": "！", "label": null }
  ],
  "output": "[挨拶]、[人名][敬称]！"
}
```

### 例 2 意味カテゴリと機能語

```json example
{
  "input": "今日は月がきれいですね",
  "tokens": [
    { "src": "今日", "label": "時間" },
    { "src": "は", "label": null },
    { "src": "月", "label": "天体" },
    { "src": "が", "label": null },
    { "src": "きれい", "label": "評価" },
    { "src": "です", "label": null },
    { "src": "ね", "label": null }
  ],
  "output": "[時間]は[天体]が[評価]ですね"
}
```

## 6. Workers AI 向けシステムプロンプト案

```text
あなたは日本語の文章を分かち書きし、各語に文脈に沿った意味のラベルを付ける変換器です。入力文を欠落なく分割し、次の JSON だけを出力してください。説明文やコードブロックは出力しません。

{"tokens":[{"src":"原文の断片","label":"ラベル または null"}]}

規則
- すべての src を先頭から順に連結すると、入力と空白・改行を含めて完全に一致すること。
- 空白を含め、入力の文字を 1 文字も省略・追加しない。空白は前後の断片に含めて残す。
- 空白、改行、記号（！？、。…〜など）、絵文字、笑、w、伸ばし棒ー、小書き文字（ゥ・ォなど）は label を null にして原文のまま残す。
- 助詞・助動詞・補助動詞などのひらがなだけの機能語（は・も・が・を・の・に・と・で・て・だ・です・ね・よ など）は label を null にして原文のまま残す。
- 漢字・カタカナ・アルファベットを含む語は、内容語（名詞・動詞・形容詞・副詞など）や固有名詞なので、label を null にせず必ずラベルを付ける。ひらがなだけの内容語（おはよう など）にもラベルを付ける。ラベルは原文の語そのものにしない。括弧や空白を含めない。10 文字以内の短い名詞句にする。
- ラベルが src と同じ文字列になるときは、上位の意味カテゴリに言い換える（光 は [現象]、名前 は [呼称]）。
- ラベルは意味カテゴリか発話機能だけを使う。
  1. 句や文の役割が明らかな定型句・掛け合い・感嘆は発話機能（挨拶、感謝、呼びかけ、返事、問いかけ、合いの手、掛け声、感嘆、命令、要求、願望、肯定、否定、宣言、評価 など）。
  2. それ以外の内容語は、文脈に沿った意味カテゴリ（人名、地名、国名、企業名、あだ名、敬称、天体、気象、場所、色、味、季節、体の一部、時間、期間、数字 など）。
- 品詞名（名詞、動詞、形容詞、助詞、助動詞 など）、その細分類（格助詞、終助詞 など）、活用形（連用形、命令形 など）はラベルに使わない。
- 人称は 一人称、二人称、三人称 を使う。外国語は 英語、アルファベット を使う。
- 原則は 1 形態素 1 ラベル。姓名・複合名称・定型句は 1 つのラベルにまとめる。
- 同じ語には同じラベルを付ける。リフレインは同じラベル列にする。
```

Workers AI の JSON モード（`response_format` には 1.1 のスキーマから `label` の `pattern` を除いたものを渡す）を使い、プロンプトの後に 5 章から数件を入出力の例として添える。ラベルの文字種は `response_format` では強制されない。応答は 2 章の検証（`pattern` を含む）を通してから 1.2 の規則で文字列に組み立てる。

## 7. 例の検証

5 章の例はすべて 1 章・2 章の規則に従う。`json example` の各ブロックについて、スキーマの `label` パターン、`src` の連結と `input` の一致、保持対象の判定、`output` の組み立てを機械的に確認できる。
